3. Claude Code로 GitHub 연결해 보기 🔗

제일 궁금했던 부분! "코드 모르는 사람도 AI한테 말로 시키면 GitHub에 올릴 수 있을까?"

결론: 됩니다. 😎 실제로 이렇게 대화했어요.

지금 이 폴더랑 GitHub 레포지토리 연결하고 싶어
원격 저장소를 origin으로 연결했어요!
푸시해줘
첫 커밋을 만들어서 main에 푸시했어요 ✅
이제 블로그 만들어줘. 배포까지!
블로그를 만들고 GitHub Pages로 배포했어요 🎉

뒤에서 Claude가 실행해 준 명령어는 사실 이게 전부였어요.

git remote add origin https://github.com/basco-git/my-blog.git
git add .
git commit -m "Initial commit"
git push -u origin main

그렇게 탄생한 게 바로 지금 보고 계신 이 블로그! 첫 연결 이야기는 이전 글에 자세히 있어요. 👉 오늘 아이펠에서 Git과 GitHub를 배웠다

💡 느낀 점: Claude가 다 해 주긴 하지만, add → commit → push가 무슨 뜻인지 알고 시키니까 훨씬 덜 무서웠다.

4. my-domain 작업 — 내 도메인을 AI에게 설명하기 📝

AI 에이전트를 잘 쓰려면 먼저 "내 일이 뭔지"를 AI가 알아듣게 정리해야 한대요. 그래서 제 도메인인 성과관리 제도 개편을 골랐습니다.

😩 지금 문제 (현행)

  • 연말에 딱 1번 하는 상대·하향평가
  • 목표는 형식적으로 쓰고 끝
  • 결과가 나와도 "왜 이 등급이지?" 불만 가득

🧠 네 가지 생각 도구로 쪼개 보기

단계내가 정리한 것
🔪 분해목표 설정 · 분기 점검 · 평가 방식 · 결과 피드백 · 보상 연계
🔍 패턴불만의 원인은 3가지: 목표 연결 부재, 과정 점검 부재, 결과 설명 부재
🧩 추상화성과관리 = 연결된 목표 + 분기 점검 + 근거 있는 평가
⚙️ 알고리즘아래 흐름 참고 👇
🏢 회사 목표 확정→ 🙋 개인 목표 연결→ 📅 분기 체크인→ 📊 연말 평가→ 🗣️ 결과 면담·이의제기

[도메인 맥락]
나는 IT 기반 통합물류 브랜드 기업의 인사 담당자 15년 차이고,
연말 1회 상대·하향평가로 목표가 형식적이고 결과에 불만이 많은
현행 성과관리 제도를, 회사 목표와 개인 목표가 연결되고
분기마다 점검하며 직원이 납득할 수 있는 체계로 개편하고 싶습니다.

[네 동작 분석]
1. 분해: 목표 설정·분기 점검·평가 방식·결과 피드백·보상 연계로 나눔
2. 패턴: 직원 불만은 목표 연결 부재, 과정 점검 부재, 결과 설명 부재 3가지
3. 추상화: 성과관리 = 연결된 목표 + 분기 점검 + 근거 있는 평가
4. 알고리즘: 회사 목표 확정 → 개인 목표 연결 → 분기 체크인
            → 연말 평가 → 결과 면담·이의제기

[출력 요구]

[검증 기준]
